# Avito Intelligence Bot

Личный Telegram-бот поверх существующего парсера `avito.py`. Старый CLI остаётся доступным. Бот хранит несколько поисков, объявления, цены, оценки и очередь уведомлений в SQLite.

## Быстрый запуск

1. Скачайте репозиторий и установите [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. В папке проекта выполните `cp .env.example .env` (Windows PowerShell: `Copy-Item .env.example .env`).
3. Создайте бота у [@BotFather](https://t.me/BotFather), скопируйте токен в `TELEGRAM_BOT_TOKEN`.
4. Узнайте свой числовой Telegram ID через надёжный способ, например собственный бот `getUpdates`, и внесите его в `TELEGRAM_ALLOWED_USER_IDS`. Можно указать несколько ID через запятую.
5. Запустите:

```bash
uv sync
uv run python -m intelligence
```

Программа ожидает непустые токен и список разрешённых ID. Не помещайте `.env` в Git. Если токен был опубликован в переписке, перевыпустите его через @BotFather. Для ежедневной работы консоль не нужна: отправьте боту `/start`, нажмите «Новый поиск» или просто вставьте ссылку на страницу поиска Авито, затем укажите модель, память и название. После создания откройте карточку поиска и настройте условия. Пауза и возобновление доступны там же.

Токен Telegram для нового бота не читается из старого `data/telegram.json`, поэтому существующий CLI продолжает использовать собственную конфигурацию независимо.

## Docker

```bash
cp .env.example .env
# Заполните токен и Telegram ID в .env
docker compose up -d --build
docker compose logs -f bot
```

`data/` и `output/` привязаны к папкам на хосте; они переживают пересборку. Команда обновления: `git pull && docker compose up -d --build`. Перед обновлением сохраните `data/`, например `tar -czf avito-backup.tar.gz data/` при остановленном боте. На Windows используйте архиватор для папки `data`.

## Что происходит после добавления

Разбор URL и сбор страниц выполняют исходные `link_resolver` и `CalmClient`. Источник иногда ограничивает выдачу примерно 30 страницами; параметр `SCAN_PAGE_LIMIT` по умолчанию 30. Бот сохраняет каждую обработанную страницу и продолжает со следующей после перезапуска. Первоначальные объявления помечаются как исходная выборка и не вызывают уведомлений. После завершения сбора идёт проверка первых `WATCH_PAGES` страниц каждые `CHECK_INTERVAL_SECONDS` (не менее пяти минут). Если прочитана вся доступная выдача, отсутствовавшие объявления помечаются `not_seen`, что не означает подтверждённую продажу.

Рыночная оценка строится по медиане сопоставимых объявлений после очистки неисправных и статистических выбросов. Для группы нужно минимум пять предложений. Модель iPhone, объём памяти и явно указанное состояние выделяются отдельно; у других товаров группировка начинается с первой части заголовка. Оценка относится к ценам предложений, а не к суммам состоявшихся сделок. Недостаточная выборка показывается явно.

В карточке можно менять модель, память, цену, состояние, допустимый тип продавца, режим уведомлений, порог скидки, баллы и интервал. Для режима «Не дороже суммы» дополнительно задайте «Лимит уведомления». Необязательную сумму можно сбросить символом `-`. В общем разделе «Настройки» меняются тихие часы и включается сводка раз в 12 часов. В «Базе объявлений» доступны подробная карточка и избранное. Исключение продавца работает только при наличии его ID в ответе Авито. Кнопка Excel выгружает пять листов. `data/intelligence.sqlite3` и `data/intelligence.log` сохраняются локально.

Кнопка «Найти объявление» открывает объявления конкретного мониторинга: есть поиск по части названия, сортировка по новизне и цене, подборка выгодных вариантов и переход между страницами. Символ `-` сбрасывает текстовый запрос. «Проверить сейчас» ставит активный мониторинг в очередь на ближайший проход планировщика. Для уведомлений о новых объявлениях бот сверяет просмотры на странице объявления: вероятные повторные публикации скрываются, а недоступная проверка явно отмечается как неподтверждённая. Снижение цены уже известного объявления проверкой новизны не блокируется.

Если парсер сообщает об ошибке, статус становится `source_unavailable`, а следующая попытка откладывается. В карточке видны ошибка и время последней успешной проверки. Очередь неотправленных уведомлений сохраняется в БД и повторяется с ограниченной задержкой. После SIGTERM приложение останавливает фоновую задачу; активные поиски восстанавливаются из БД при следующем запуске.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен @BotFather, обязателен |
| `TELEGRAM_ALLOWED_USER_IDS` | Числовые ID через запятую, обязательны |
| `DATABASE_URL` | SQLite URL, по умолчанию `sqlite:///data/intelligence.sqlite3` |
| `CHECK_INTERVAL_SECONDS` | Интервал 300–86400 секунд |
| `REQUEST_DELAY_SECONDS` | Пауза парсера 10–300 секунд |
| `SCAN_PAGE_LIMIT` | До 30 страниц исходного сбора |
| `WATCH_PAGES` | Сколько первых страниц проверять после сбора, 1–5 |
| `QUIET_HOURS_START`, `QUIET_HOURS_END` | Часы без отправки, 0–23 |
| `TIMEZONE`, `LOG_LEVEL` | Часовой пояс и уровень журналирования |
| `AI_ENABLED`, `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL` | Необязательный OpenAI-совместимый API для текста и фото |
| `AI_DAILY_REQUEST_LIMIT`, `AI_MAX_IMAGES` | Суточный предел запросов и число фотографий на объявление |

Настройки AI не обязательны для основного мониторинга. API-ключ не сохраняется в БД. Дополнительный AI-анализ вызывается только для кандидатов перед уведомлением. Фото сначала скачиваются с разрешённых доменов Авито и обрабатываются локально; если фото не было обработано, визуальных выводов не будет. Суточное число запросов сохраняется в `data/ai_usage.json`. Оценки AI помечаются как предположения. Сейчас поддерживается OpenAI-совместимый формат API; значение `AI_PROVIDER` зарезервировано для будущих адаптеров.

## Старые поиски

При старте бот идемпотентно импортирует поиски, для которых одновременно есть `searches/<имя>.json` и `data/searches/<имя>/`. Импортированные поиски поставлены на паузу, чтобы не начинать наблюдение без проверки условий. Оригинальные файлы не удаляются. Первый ID в `TELEGRAM_ALLOWED_USER_IDS` становится владельцем импортированных поисков.

## Проверки

```bash
uv run pytest -q
uv run ruff check intelligence tests_bot
uv run ruff format intelligence tests_bot --check
```

Для проверки живого Telegram и Авито нужны собственный токен и реальная доступность обоих сервисов. Автоматические тесты используют искусственные ответы и не обходят CAPTCHA. Ограничение доступа к источнику нельзя считать продажей объявления.

## Известные ограничения текущей версии

- Мониторинг охватывает только первые `WATCH_PAGES` страниц; объявления за их пределами могут быть пропущены. Проверка новизны по просмотрам эвристическая: возможны ошибки около полуночи и при неполных данных страницы. Объявления с новым ID не объединяются с прежними автоматически.
- Структура фотографий в ответах Авито меняется; если публичные URL фотографий не обнаружены, бот продолжит работать без визуального анализа. Поиск повторов сравнивает хеши только уже обработанных фотографий кандидатов.
- Сводка отправляет первые ожидающие предложения каждые 12 часов; при очень большой очереди часть предложений попадёт в следующую сводку. Кнопка «Лучшие предложения» показывает и старые подходящие объявления из базы.
- При аварии между успешной отправкой Telegram и фиксацией в SQLite возможно повторное уведомление.
- Полноценная живая проверка Telegram, Авито и сборки Docker в текущей среде не проводилась.
